# exp-v1 follow-ups: the snapshot curriculum against a control, and each reward change alone and combined.
#
# Single-node jobs, at most 2 at a time (cluster admin, 2026-11-05: one node per job, up to 2 nodes per user).
# exp-v1 ran on 2 nodes x 12 envs; one node with 24 envs collects the same 3072 steps per update, so
# the PPO hyperparameters are the same and these compare directly with runs/exp-v1. 24 envs need ~28 CPUs and
# ~40 GB, which only bowser and chungus have. Submit after exp-v1 (job 1365) finishes:
#   SBATCH_EXTRA="--cpus-per-task=28 --mem=52G --exclude=adrian --dependency=afterok:1365" \
#     MAX_CONCURRENT=2 hpc/submit.sh --sweep hpc/sweeps/exp-v1-ablation.txt
# Pairs run side by side in this order.
#
# 1. Curriculum vs control, both continuing from exp-v1's final weights:
#   exp-v1-curr   --snapshot-waves 20-45: half of new episodes start from banked wave 20-45 snapshots
#   exp-v1-ctrl   identical without the curriculum
# 2-3. Reward ablation, from scratch. exp-v1 plateaued near wave 20 with entropy ~0.15 and never caught a
# Pokemon: every member standing faints at game over, so a team of n pays 0.1 * n(n+1)/2 (3: 0.6, 6: 2.1)
# and catches earn no EXP.
#   exp-coef-v1   --ent-coef 0.03 (was 0.01): keep exploring (balls, lures, switches)
#   exp-go-v1     --faint-gameover 1.0: losing the run costs the same whatever the team size
#   exp-alive-v1  --alive-coef 0.05: per wave cleared, 0.05 * (members not fainted) / 6
#   exp-all-v1    all three
